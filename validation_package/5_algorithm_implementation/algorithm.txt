1. TRUST CALCULATION (Bayesian Lightweight Fusion)
--------------------------------------------------
File: iah_edsd_engine.py (class IAHEDSDDetectionEngine)

The trust score for each node is computed as a weighted Bayesian fusion of
three independent evidence channels:

  T_i(t) = w1 * T_rssi + w2 * T_seq + w3 * T_rate

Where:
  - T_rssi = RSSI spatial fingerprint trust (1.0 if delta_RSSI < 5.0 dBm, else
    linearly decayed toward 0.0 based on deviation magnitude)
  - T_seq  = Sequence number continuity trust (1.0 if sequence gap <= 3, else
    decayed based on gap size)
  - T_rate = Transmission rate anomaly trust (1.0 if packet rate within expected
    bounds, else decayed)
  - Weights: w1=0.50, w2=0.25, w3=0.25 (RSSI dominates for spoofing detection)

Temporal decay is applied via Exponentially Weighted Moving Average (EWMA):
  T_i(t) = alpha * T_i(t) + (1 - alpha) * T_i(t-1),  alpha = 0.3

Trust is NOT random — it is derived from measurable physical-layer and
MAC-layer features of each incoming packet.


2. EVENT-DRIVEN TRIGGER (Adaptive Threshold)
---------------------------------------------
File: iah_edsd_engine.py → evaluate_packet() method

Detection is triggered ONLY when anomalous conditions are detected, NOT on
every packet. The event-driven trigger fires when ANY of these conditions hold:

  EventTrigger = (T_i < 0.60) OR (delta_RSSI > 5.0 dBm) OR (seq_gap > 3)

This replaces continuous cryptographic verification (which costs 90 mJ/packet)
with lightweight checks (0.002 mJ/packet), achieving 97.88% energy savings.

When the event trigger fires:
  1. ML classifier (Random Forest) is invoked on the feature vector
  2. EWS (Early Warning Score) is updated
  3. If T_i < 0.60, ECDSA-P256 signature audit is triggered (Phase 7)


3. DETECTION LOGIC (Multi-Factor Isolation Rule)
-------------------------------------------------
File: iah_edsd_engine.py → evaluate_packet() method

A node is declared SPOOFED and ISOLATED only when ALL three conditions are
simultaneously satisfied:

  Isolate_i = (T_i(t) < 0.60) AND (EWS_i(t) > 0.40) AND (delta_RSSI > 5.0 dBm)

This prevents false positives from:
  - Transient channel fading (fails EWS persistence check)
  - Legitimate node movement (fails multi-factor combination)
  - One-time sequence resets (fails trust decay check)


4. EARLY WARNING SCORE (EWS) TEMPORAL AGGREGATION
---------------------------------------------------
File: iah_edsd_engine.py → _update_ews() method

EWS provides temporal persistence detection to distinguish persistent attackers
from transient noise:

  EWS_i(t) = beta * EWS_i(t-1) + (1 - beta) * I(suspicious)

Where:
  - beta = 0.90 (decay factor)
  - I(suspicious) = 1 if current packet triggers event, else 0
  - Persistent attackers → EWS approaches 1.0
  - Transient fading → EWS stays < 0.20


5. SPOOFING ATTACK SIMULATION (Not Fake)
------------------------------------------
File: ns3_spoofing_simulation.py → AttackerApp class

Attackers are NOT just labeled — they actively:
  a) Clone a legitimate node's ID (identity spoofing)
  b) Transmit from a DIFFERENT physical location (different RSSI)
  c) Use random/forged sequence numbers (breaks continuity)
  d) Transmit at higher rates during burst windows
  e) Sign packets with WRONG keys (fails ECDSA verification)

The detection algorithm catches these through physical-layer inconsistencies,
NOT through pre-labeling.


6. ENERGY MODEL (Realistic, Not Estimated)
--------------------------------------------
File: ns3_spoofing_simulation.py → EnergyTracker class

Energy consumption is tracked per-packet, per-node:
  - TX energy = packet_size_bytes * 1.67e-6 J/byte
  - RX energy = packet_size_bytes * 1.80e-6 J/byte
  - Sleep energy = elapsed_time * 1.0e-8 J/sec
  - ECDSA audit = 90.0 mJ per signature verification (when triggered)
  - ML inference = 0.002 mJ per classification (lightweight)

Energy is deducted from each node's battery in real-time during simulation.
When a node's energy reaches 0, it is marked as dead.
